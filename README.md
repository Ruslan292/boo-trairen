# БОО — тренажёр

Веб-приложение для подготовки по билетам безопасного обращения с оружием.
В базе **20 билетов и 200 вопросов** из файла «Билеты БОО с ответами 2026.docx».
Тексты и ключи ответов взяты из документа; одинаковые вопросы в разных билетах
сохранены на своих местах.

## Возможности

- **Обучение:** все вопросы подряд или выбранный билет, проверка после каждого ответа.
- **Учебный экзамен:** выбранный или случайный билет, таймер, свободный переход
  между вопросами и результаты после завершения. Длительность — 5, 10 или 20
  минут; допустимое число ошибок — 0, 1 или 2. Это настройки тренажёра.
  Пропущенные вопросы считаются ошибками.
- **Работа над ошибками:** неверные и пропущенные ответы попадают в отдельный
  список. Правильный повторный ответ убирает вопрос из этого списка.
- **Прогресс:** доля изученных вопросов, точность всех попыток, история последних
  50 экзаменов. Данные хранятся в `localStorage` текущего браузера.
- **Продолжение:** незавершённая тренировка сохраняется после обновления страницы.
  Таймер экзамена продолжает идти, в том числе при закрытой вкладке.
- Адаптивный интерфейс для телефона и компьютера. В обучении можно использовать
  клавиши `1`–`3` для ответа и `Enter` для проверки или перехода.

«Изучено» означает число позиций в билетах, для которых уже проверен хотя бы один
ответ. Повторяющиеся вопросы разных билетов учитываются отдельно.
Точность — доля правильных ответов среди всех проверенных попыток.

## Запуск

Нужен **Node.js 24** (в облачной среде уже доступен). Внешних npm-зависимостей нет:
установка пакетов и сборка не требуются.

```sh
cd /workspace/boo-trairen
npm start
```

Сервер раздаёт приложение из `public/` на порту **3000**. При необходимости:

```sh
PORT=8080 HOST=0.0.0.0 npm start
```

Сервер нужен только для выдачи статических файлов; приложение можно разместить
на статическом хостинге, разместив содержимое `public/` в корне сайта. Аккаунты,
серверная база и синхронизация между устройствами в текущей версии отсутствуют.

### Публикация на GitHub Pages

Файл `.github/workflows/pages.yml` проверяет приложение и публикует только
содержимое `public/` при отправке изменений в `main` или ручном запуске workflow.
В настройках репозитория **Settings → Pages → Source** выберите **GitHub Actions**.
После успешного выполнения шаг **Deploy** покажет адрес опубликованного сайта.
Для запуска публикации отправьте файлы приложения и workflow в репозиторий.
Относительные пути поддерживают размещение в подкаталоге репозитория.

## Проверки

Для проверки источника данных дополнительно нужен **Python 3.12**.

```sh
npm test
```

Команда запускает тесты логики тренажёра и сверку всех 200 вопросов и ответов
с исходным DOCX. Проверяется также отказ от извлечения при неверных ключах,
пропущенных строках или конфликтующих ответах.

Браузерная проверка использует Python Playwright и Chromium, доступные в текущей
облачной среде. При запущенном сервере:

```sh
python3 tests/browser_smoke.py
```

Проверяются обучение, повтор ошибок, экзамен, сохранение и восстановление прогресса,
завершение по таймеру и мобильная раскладка.

## Обновление базы

Исходный документ не изменяется при извлечении. После его обновления:

```sh
npm run extract
npm test
```

Скрипт использует стандартную библиотеку Python, требует 20 билетов по 10
вопросов и явные ключи 1–3 в столбце «Верно». При несоответствии структуры
завершается с ошибкой, не заменяя существующую базу.

## Структура

```text
public/                    Статическое приложение
  app.js                   Интерфейс и обработчики действий
  model.js                 Прогресс, сессии, подсчёт результатов
  questions.json           База, извлечённая из DOCX
scripts/
  serve.mjs                HTTP-сервер без внешних зависимостей
  extract_questions.py     Проверка и извлечение документа
tests/                     Проверки логики, источника и браузера
```
